# RichInventor 仕様書

対象: Inventor 2025.4 / .NET 8 / C#
最終更新: 2026-10-13

---

## 1. 全体の考え方

- **Core と Commands を分ける。**
  `Core/` に Inventor API を叩く処理(STL 書き出し・ドキュメント走査・設定)を置き、
  `Commands/` にはリボンボタン 1 個ぶんの「どういう状況で何を対象にするか」だけを書く。
  機能が増えても Core は共有されるので、同じコードが散らばらない。

- **止めずに続けて、最後にまとめて報告する。**
  1 件失敗しても残りの書き出しは続行し、最後に「新規 / 上書き / 失敗」の件数と
  エラー内容を 1 つのダイアログで見せる。

- **破壊的なことは確認してから。**
  出力先フォルダは毎回ユーザーに選ばせる。既定値は提示するが、勝手には決めない。

- **COM のコールバック境界で例外を止める。**
  ボタンの `OnExecute` から Inventor 側に例外が伝播すると Inventor が不安定になるため、
  `RichCommand.OnExecuteInternal` で必ず捕まえてダイアログにする。

## 2. STL 出力の仕様

### 2.1 既定の設定

| 項目 | 既定値 | 意味 |
|---|---|---|
| 単位 | ミリメートル | `ExportUnits = 5` |
| 精度 | 高精度 | `Resolution = 0` |
| 形式 | バイナリ STL | `OutputFileType = 0` |
| 色情報 | 含めない | `ExportColor = false` |

色情報を既定で切っているのは、バイナリ STL の属性バイトに色を埋める方式が
標準ではなく、スライサによっては誤解釈するため。3D プリント用途では入れない方が安全。

いずれも `settings.json` で変更できる(README の[設定](../README.md#設定)を参照)。

### 2.2 STL トランスレータのオプション値(実測)

Inventor の STL トランスレータ
(AddIn ID `{533E9A98-FC3B-11D4-8E7E-0010B541CD80}`)が受け取る値。
**Inventor 2025.4 で実際に書き出して寸法・三角形数から逆算し確定させたもの。**

`ExportUnits` — 28.0 mm 角の実部品を各値で書き出したときの STL 上の寸法:

| 値 | 出力寸法 | 意味 |
|---|---|---|
| 2 | 1.102 | インチ |
| 3 | 0.092 | フィート |
| 4 | 2.800 | センチメートル |
| **5** | **27.998** | **ミリメートル** ← 既定 |
| 6 | 0.028 | メートル |
| 7 | 27998 | ミクロン |

> 0 と 1 もミリメートルになったが、これはドキュメントの単位が mm だったためで、
> 単位指定として意味を持つ値ではないと思われる。明示的に `5` を使うこと。

`Resolution` — 同じ部品での三角形数:

| 値 | 三角形数 | 意味 |
|---|---|---|
| **0** | 2800 | **高精度** ← 既定 |
| 1 | 1584 | 中精度 |
| 2 | 1020 | 低精度 |
| 3 | 256 | カスタム(`SurfaceDeviation` 等を別途指定) |
| 4 | 900 | Brep(モデルの表示メッシュをそのまま使う。Inventor の既定値) |

`OutputFileType`: `0` = バイナリ、`1` = ASCII(先頭が `solid ASCII` になることを確認)

トランスレータが持つオプションの全一覧(実機で列挙):
`ExportUnits` / `Resolution` / `AllowMoveMeshNode` / `SurfaceDeviation` /
`NormalDeviation` / `MaxEdgeLength` / `AspectRatio` / `ExportFileStructure` /
`OutputFileType` / `ExportColor`

### 2.3 書き出しの手順

`Core/StlExporter.cs` の `ExportDocument`:

1. `ApplicationAddIns.ItemById[...]` で `TranslatorAddIn` を取得し、未活性なら `Activate()`
2. `TransientObjects.CreateTranslationContext()` に `kFileBrowseIOMechanism` を設定
3. `HasSaveCopyAsOptions` で**既定オプションを取り出してから**、変えたい項目だけ上書きする
   (自前で全項目を `Add` すると Inventor 側の項目追加に追従できなくなる)
4. `DataMedium.FileName` に出力先を入れて `SaveCopyAs`
5. **書き出し後にファイルの存在を確認する**
   `SaveCopyAs` は例外を投げずに失敗することがあるため

## 3. 用途別STL出力

### 3.1 動作

リボンの種類に応じて、用途を分けたボタンを表示する。

| リボン | ボタン | 対象 | 出力先の既定 |
|---|---|---|---|
| Assembly | 選択部品を出力 | 選択した各パーツ／サブアセンブリ | アセンブリと同階層の `3DPstl\` |
| Assembly | 3DP 部品を出力 | ファイル名に目印を含む全参照パーツ | アセンブリと同階層の `3DPstl\` |
| Part | 開いているパーツを出力 | アクティブなパーツ1件 | パーツのフォルダ |

対象外リボンにはボタンを表示しない。コマンド側にもドキュメント種別の防御的な
検査を残し、リボンのカスタマイズ等から誤って実行されても書き出さない。

### 3.2 選択の解釈

- モデルツリーで部品を選んだ場合 → その `ComponentOccurrence`
- 画面上で部品の**面やエッジ**を選んだ場合 → `ContainingOccurrence` を辿って部品を特定する
  (`FaceProxy` など型が多岐にわたるため、型ごとのキャストではなく遅延バインドで取得している)
- **サブアセンブリを選んだ場合** → それを結合した **1つの STL** になる
- 同じ部品を複数インスタンス選んでも、STL は **1個だけ** 出力する
- 選択が空なら案内を表示して終了し、アセンブリ全体は暗黙に出力しない

### 3.3 出力される座標系

部品を個別に書き出すとき、STL は **その部品自身の座標系(モデリングしたときの向き)**
で出力される。アセンブリ上での配置位置・姿勢は反映されない。
書き出し対象として渡しているのがオカレンスではなく参照先のパーツドキュメントそのもの
だからで、3D プリント用途ではこれが望ましい(スライサ側で並べ直すため)。

選択したサブアセンブリは、そのサブアセンブリ内部の配置を保って1つに結合される。
アクティブなアセンブリ全体を1つのSTLにする機能は、この3ボタンには含めない。

### 3.4 開いているパーツ

`Application.ActiveDocument` がパーツである場合、その1件だけを出力する。
ほかのウィンドウで開いているパーツや、アセンブリが内部的にロードした参照パーツは
対象にしない。

## 4. 3DP 部品を出力

### 4.1 動作

1. アクティブなアセンブリの `AllReferencedDocuments` を走査する
2. パーツ(`kPartDocumentObject`)だけを残す
3. ファイル名に目印(既定 `3DP`)を含むものを残す
4. 名前順に並べて一覧を提示し、確認をとる
5. 出力先フォルダを選ばせる(既定 = アセンブリと同階層の `3DPstl\`)
6. 全件書き出して結果を報告する

アセンブリ以外で実行した場合は警告を表示して終了する。通常はAssemblyリボンにだけ
ボタンが表示されるため、リボンのカスタマイズ等から実行された場合の防御処理となる。

### 4.2 なぜ AllReferencedDocuments を使うのか

`AllReferencedDocuments` は **直接参照も間接参照もすべて** 返し、かつ
**同じファイルは1回しか返さない**。
つまり「サブアセンブリの再帰探索」と「同一部品の重複排除」がこれ1つで両方片付く。
`Occurrences` を自前で再帰する必要はない。

> 実測: `MeasureEncoderUnit_all_v2.iam`(直下オカレンス 41 個)に対し
> `AllReferencedDocuments` は 35 件(パーツ 32 / サブアセンブリ 3)を返し、
> `3DP` を含むパーツは 4 件だった。

### 4.3 走査の設定

`settings.json` で調整する(再ビルド不要)。

| キー | 既定 | 説明 |
|---|---|---|
| `PrintMarker` | `"3DP"` | 目印にする文字列 |
| `MarkerIgnoreCase` | `false` | `true` にすると `3dp` / `3Dp` も拾う |
| `ExcludeOldVersions` | `false` | `true` にすると `OldVersions\` / `backup\` 配下への参照を無視する |

`ExcludeOldVersions` が既定で `false` なのは、`AllReferencedDocuments` が返すのは
**実際に参照されているファイルだけ**であり、`OldVersions\` の中身は通常そこに現れないため。
既定で除外すると、意図して旧版を参照している場合に黙って取りこぼす。

## 5. 出力ファイル名

- 基本は **元のファイル名の拡張子を `.stl` に替えたもの**
  `3DP_BenzSpacer.ipt` → `3DP_BenzSpacer.stl`
  (既存の `3DPstl\` フォルダでの付け方に合わせている)
- Windows のファイル名に使えない文字は `_` に置換する
- **同名の別ファイル**が同じ書き出しに含まれた場合は `_2`, `_3` と連番を付ける
  (別フォルダにある同名パーツが互いを上書きするのを防ぐ)
- 出力先に同名ファイルが既にある場合は **上書きする**。
  上書きした件数は完了ダイアログに「上書き」として報告される

## 6. リボン UI

| 項目 | 値 |
|---|---|
| タブ | `RichInventor` (内部名 `RichInventor:Tab`) |
| パネル | `STL 出力` (`RichInventor:Panel:Stl`) / `寸法PDF` (`RichInventor:Panel:DimensionPdf`) / `配置` (`RichInventor:Panel:Placement`) |
| 出す対象 | `Part` リボンと `Assembly` リボン(コマンドごとに表示を制限) |
| ClientId | `{0165C313-EE82-48FF-9894-36CAF30D298F}` |

Inventor はリボン構成をユーザープロファイルに保存するため、アドインを再ロードすると
同じタブ/パネルが既に存在することがある。`RibbonBuilder` はタブ・パネル・ボタンの
すべてを「あれば使う、無ければ作る」で処理しており、重複しない。
旧版で対象外リボンに保存されたコントロールは、起動時にパネルから削除する。

| リボン | 表示するコマンド |
|---|---|
| Part | 開いているパーツを出力、開いているパーツの寸法PDF、設定 |
| Assembly | 3DP 部品を出力、選択部品を出力、ASP部品の寸法PDF、選択部品の寸法PDF、最大平面を接地、選択部品を接地、設定 |

コマンドは `RichCommand.Panel`(`RibbonPanelKind`)で置き場所のパネルを指定する。
そのリボンに出すボタンが 1 つも無いパネルは作らない(Part リボンに `配置` パネルは出ない)。

アイコンは `UI/IconFactory.cs` でコードから描いている(配布物を DLL 1 つに保つため)。
Inventor は `IPictureDisp` を要求するので、`AxHost.GetIPictureDispFromPicture` で変換し、
失敗した場合は `OleCreatePictureIndirect` にフォールバックする。
どちらも駄目ならアイコン無しでボタンだけ登録する。

## 7. 設定ファイル

`%APPDATA%\RichInventor\settings.json`。無ければ初回に既定値で自動生成される。

読み込みは**ボタンを押すたび**に行うので、Inventor を再起動せずに変更が反映される。
JSON が壊れていても例外にせず既定値で動き続ける(設定ミスで機能が使えなくなるより、
既定で動く方がよいという判断)。

## 8. 寸法PDF

- Assemblyには `ASP部品の寸法PDF` と `選択部品の寸法PDF`、Partには
  `開いているパーツの寸法PDF` を表示する。独立した `寸法PDF` パネルに置く。
- `ASP` はファイル名の大文字を区別する。アセンブリの実オカレンスを再帰走査し、
  抑制されたものを除いて個数を数える。選択したサブアセンブリも葉のパーツまで展開する。
- 一時図面に一覧シートと部品シートを作り、InventorのPDFトランスレータ
  `{0AC6FD96-2F4D-42CE-8BE0-8AEA580399E4}` で1冊へ出力する。
  保存ダイアログで出力先を指定し、元モデルと一時図面は保存しない。
  日本語の注記・表には `Noto Sans JP` を明示する（実行PCにフォントが必要）。
- 部品の最小外接直方体から長手X・幅Y・高さZを決める。外形最小端を原点とし、
  cmで返るInventor APIの値をmmへ換算する。穴の入口中心座標もこの軸で示す。
- 穴フィーチャーから径・種類・タップ規格・深さを取得する。形状の内側円筒面と
  円形エッジからも穴を拾い、加工属性が確定できなければ「不明」とする。
  肉厚は対向する内外面の距離が一致する場合だけ表示する。
- ±X/±Y/±Zの図面ビューを生成し、可視線と隠れ線の2D幾何を比較する。
  平面内の回転で一致するビューは1枚に統合する。複雑な曲線を比較できないときは
  安全側として省略しない。
- 一覧は最大18部品/ページ、各部品の先頭ページは穴6件まで、以降の穴一覧は
  22件/ページで分割する。PDFの既定用紙はA3横。

## 9. 最大平面を接地

`Core/GroundAligner.cs`(ロジック)と `Commands/GroundLargestFaceCommand.cs`(ボタン)。
Assembly リボンの `配置` パネルに置く。

1 つのコマンドクラスを `GroundMode` で 2 つのボタンに使い分ける(寸法PDF の `DimensionPdfMode` と同じ形)。

| ボタン | 内部名 | 対象 |
|---|---|---|
| 最大平面を接地 | `RichInventor:GroundLargestFace` | アセンブリ直下の全オカレンス |
| 選択部品を接地 | `RichInventor:GroundLargestFaceSelected` | 選択から寄せた直下のオカレンス(§9.6) |

### 9.1 動作

1. アクティブなアセンブリ直下の `Occurrences` を走査する(再帰しない)
2. 各オカレンスの平面を集め、**基準部品**を 1 つ決める(§9.2)
3. 基準以外のオカレンスについて、最大平面と拘束できるかを判定する(解析だけで、モデルは変えない)
4. 基準・拘束する件数・固定を解除する件数・付け直す件数・スキップする件数を見せて確認をとる
5. 1 つのトランザクション `最大平面を接地` の中で、基準部品を固定し、各部品の最大平面を
   `AddFlushConstraint(部品の面, 基準部品の面, 0)` で拘束する
6. 拘束・スキップ・失敗の一覧を報告する

アセンブリ以外、またはインプレース編集中(`ActiveOccurrence` が有る)なら警告して終了する。
基準部品のほかに拘束できる部品が無ければ(選択が 1 個だけ等)、案内を出して終了する。

> 以前の版はアセンブリの XY 平面(`settings.json` の `GroundPlane`)を基準にしていたが、
> 部品どうしをそろえる方式に置き換えた。`GroundPlane` は削除済みで、古い設定ファイルに残っていても無視される。

### 9.2 基準部品と最大平面の選び方

- パーツは `ComponentOccurrence.SurfaceBodies`、サブアセンブリは `SubOccurrences` を
  再帰して葉パーツの `SurfaceBodies` を見る。どちらもアセンブリ文脈の `FaceProxy` が返る
- `IsSolid && Visible` のボディの `kPlaneSurface` の面だけを候補にし、
  `Face.Evaluator.Area`(cm²)が最大のものを選ぶ
- サブアセンブリは 1 つの剛体として扱い、内部の部品は個別に拘束しない
- **基準部品**: 抑制中・パターン要素・平面なしを除いた範囲内のオカレンスが候補。
  固定(グラウンド)されている候補があればその中から、無ければ全候補から、最大平面の面積が
  いちばん大きいものを選ぶ(同じなら `Occurrences` の並びで先のもの)。
  基準は動かさないので、ほかの拘束が付いていても候補になる
- **基準面**: 基準部品の最大平面。99.99% 以上の面が複数ある(板の表裏など)ときは、
  外向き法線がアセンブリの -Z にいちばん近い面(底面)を使う
- **各部品の面**: 最大平面。99.99% 以上の面が複数ある(立方体など)ときは、
  外向き法線が基準面の法線にいちばん近い面を選ぶ(回転量が最小になる)

### 9.3 拘束の向き

フラッシュ拘束なので、各部品の最大平面は基準面と**同一平面・同じ向き**になる。
基準面が基準部品の底面なら、全部品が基準部品と同じ床に並ぶ(本体は基準部品と同じ側に来る)。

### 9.4 対象外と既存の拘束

| 状態 | 扱い |
|---|---|
| 基準部品が固定されていない | 固定する(動かさないため) |
| 基準以外で固定されている | 固定を解除してから拘束する(API で最初に置いた部品も自動で固定される) |
| ほかの拘束・ジョイントがある | 矛盾を避けるためスキップ(基準部品は除く) |
| 抑制中 / パターン要素 / 平面が無い | スキップ |

拘束・ジョイントの有無は `AssemblyComponentDefinition.Constraints` と `.Joints` を 1 回ずつ走査し、
`OccurrenceOne` / `OccurrenceTwo` の `OccurrencePath[1]`(直下のオカレンス)に寄せて数える。
サブアセンブリ内部の面に付いた拘束もこれで拾える。

### 9.5 再実行と元に戻す

- 付けた拘束には AttributeSet `RichInventorGround` を付け、名前を `接地:<オカレンス名>` にする
- 拘束は `AddFlushConstraint(動かす部品の面, 基準の面)` の順で作るので、`OccurrenceOne` が動かした側、
  `OccurrenceTwo` が基準側になる。自前の拘束は **`OccurrenceOne` 側にだけ** 自前として数え、
  基準側では自前にも「ほかの拘束」にも数えない
  - 前回の基準部品が今回の対象になっても、「ほかの拘束あり」でスキップされない
  - 基準部品の自前拘束を外すとき、範囲外の部品がその基準に付けた拘束まで消さない
- 再実行時、対象部品の自前拘束は削除してから付け直す(重複しない)
- 基準部品に自前拘束(前回どこかにそろえられた側の拘束)があれば、削除してから固定する。
  以前の版の XY 平面への接地拘束は `OccurrenceTwo` が無いので動かした側の自前拘束として扱われ、
  同じ規則で基準部品への拘束に置き換わる
- 拘束後の `HealthStatus` が異常なら、その拘束を消して固定を戻し、失敗として報告する
- 全体が 1 トランザクションなので Ctrl+Z 1 回で元に戻る(基準部品の固定も戻る)

### 9.6 選択部品モード

`GroundAligner.SelectedTopLevelNames` が `SelectSet` から対象の直下オカレンス名を集め、
`Plan(..., only)` に渡して対象を絞る。解析・確認・適用・報告は全モードと共通。

- 要素が `ComponentOccurrence`(`ComponentOccurrenceProxy` を含む)ならそれ、そうでなければ
  `DocumentScanner.ContainingOccurrenceOf`(遅延バインドの `ContainingOccurrence`)で所属部品まで遡る。
  STL の選択出力(§3.2)と同じ解釈
- 見つけたオカレンスは `OccurrencePath[1]` で**直下のオカレンス**に寄せる。
  サブアセンブリの中の部品や面を選んでも、そのサブアセンブリ全体が対象になる
- 同じ部品の面を複数選んでも 1 件にまとまる。作業平面などオカレンスに属さない選択は無視する
- 基準部品も選択したものの中から §9.2 の規則で選ぶ。選択外の固定部品は基準にならない
- 絞り込んでも、ほかの拘束の有無の判定(§9.4)はアセンブリ全体の拘束を見て行う
- 選択外のオカレンスは解析結果にもスキップ一覧にも出さない
- 選択が空(または寄せた結果が 0 件)なら案内を表示して終了する。全部品を暗黙に処理しない

### 9.7 実機での確認(Inventor 2025.4)

非表示の別インスタンスに、固定した板 2 枚(最初に置いたもの + 明示的に固定したもの)・立方体・
サブアセンブリ・互いに拘束した 2 部品を置いて検証した。
- 全部品モード: 先に置いた固定板が基準になり、3 件を拘束、拘束済みの 2 件をスキップした。
  全件で面が基準面と同一平面・同じ向きになり、基準板は固定のまま動かなかった。
  拘束の `OccurrenceOne` は動かした側、`OccurrenceTwo` は基準板だった
- 再実行は 3 件の付け直しで、拘束数は増えなかった。Undo で固定も含めて元に戻った
- 以前の版の XY 平面への接地拘束(目印付き)は自前拘束として扱われ、基準への拘束に置き換わった
- 選択部品モード(固定板を含む選択): 固定板が基準になり、2 件を拘束、拘束済みの 1 件をスキップした。
  SubAsm は全モードと同じ 18 cm² の面を使い、選択していない部品の固定と位置は変わらなかった
- 選択部品モード(固定部品なし): 面積の大きい SubAsm が基準になって新たに固定され、動かなかった
- 選択が 1 個だけなら基準だけになり、拘束対象は 0 件になった
